# 🎮 Крестики-нолики

Веб-игра «Крестики-нолики» с сохранением результатов партий в базе данных SQLite.

Два режима игры: **против компьютера** (человек за X, компьютер за O) и
**«2 игрока»** — двое за одним устройством ходят по очереди. После каждой
партии результат сохраняется в базу и появляется в истории на главном экране.

**Стек:** Node.js + Express (бэкенд), SQLite через `better-sqlite3` (база),
чистые HTML + CSS + JavaScript (фронтенд, без фреймворков и CDN).

## 🖥 Экраны

### Экран 1 — Меню

Содержит:

- заголовок «Крестики-нолики»;
- переключатель режима: **«Против компьютера»** / **«2 игрока»**;
- поле ввода имени игрока (в режиме «2 игрока» — два поля: Игрок 1 за X и
  Игрок 2 за O);
- кнопку **«Начать игру»**;
- таблицу последних 10 игр (игроки, результат, дата);
- кнопку **«Очистить историю»**.

Если история пуста, вместо таблицы показывается текст «История пока пуста».

### Экран 2 — Игра

Содержит:

- имена игроков (в режиме с ИИ — ваше имя, в «2 игрока» — оба: `Алиса (X) vs Борис (O)`);
- индикатор текущего хода: «Ваш ход (X)» / «Ход компьютера (O)…» в режиме с ИИ,
  «Ход: Алиса (X)» в режиме «2 игрока»;
- поле 3×3;
- итог партии после её завершения;
- кнопку **«Сыграть ещё»** → возврат в меню.

В режиме «2 игрока» компьютер не участвует: крестики и нолики ходят по очереди
без задержки, поле остаётся активным всё время.

Победа определяется по горизонтали, вертикали и двум диагоналям. Ничья
фиксируется, когда поле заполнено, но победителя нет.

### Как играет компьютер

Простой ИИ с приоритетами:

1. **Выиграть самому**, если есть такая возможность;
2. **Заблокировать** победу игрока;
3. Встать в **центр**;
4. Занять **угол**;
5. Любую свободную клетку.

## 🔌 API

Базовый адрес: `http://localhost:3000`
Формат обмена — JSON. Тело любой ошибки: `{ "error": "текст на русском" }`.

### `GET /api/games`

Возвращает последние игры (не более 10), отсортированные по дате убывания.

**Тело запроса:** отсутствует

**Ответ `200 OK`:**
```json
[
  {
    "id": 22,
    "x_name": "Алиса",
    "o_name": "Борис",
    "mode": "duo",
    "result": "win",
    "played_at": "2026-10-05 14:28:08",
    "player_name": "Алиса"
  }
]
```

`result` всегда читается от лица X: `win` — победил X, `lose` — победил O,
`draw` — ничья. Поле `player_name` — legacy из ТЗ, всегда равно `x_name`
(для обратной совместимости).

Если история пуста, возвращается `200 OK` и пустой массив `[]` (не 404).

---

### `POST /api/games`

Сохраняет результат завершённой партии.

**Новое тело (оба игрока явно):**
```json
{
  "x_name": "Алиса",
  "o_name": "Борис",
  "mode": "duo",
  "result": "win"
}
```

**Legacy-тело из ТЗ (партия против компьютера):**
```json
{
  "player_name": "Алиса",
  "result": "win"
}
```

| Поле | Тип | Правила |
|---|---|---|
| `x_name` | string | обязательно (или legacy `player_name`), после `trim()` от 1 до 30 символов |
| `o_name` | string | обязательно в режиме `duo`; в режиме `ai` по умолчанию `"Компьютер"` |
| `mode` | string | необязательно, одно из: `ai`, `duo`; по умолчанию `ai` |
| `result` | string | обязательно, одно из: `win`, `lose`, `draw` (с точки зрения X) |

**Ответ `201 Created`:**
```json
{
  "id": 22,
  "x_name": "Алиса",
  "o_name": "Борис",
  "mode": "duo",
  "result": "win",
  "played_at": "2026-10-05 14:28:08",
  "player_name": "Алиса"
}
```

---

### `DELETE /api/games`

Очищает всю историю игр.

**Тело запроса:** отсутствует

**Ответ `200 OK`:**
```json
{ "deleted": 1 }
```

`deleted` — количество удалённых записей. Если история была пуста, вернётся
`{ "deleted": 0 }` — это не ошибка.

### Коды ошибок

| Код | Когда возникает | Пример |
|---|---|---|
| `400 Bad Request` | Ошибка валидации: неверный JSON, пустое/длинное имя, неизвестный `result` | `{"error":"Имя игрока: от 1 до 30 символов"}` |
| `404 Not Found` | Обращение к несуществующему пути `/api/*` | `{"error":"Неизвестный API-маршрут"}` |
| `500 Internal Server Error` | Внутренняя ошибка сервера или сбой БД | `{"error":"Не удалось сохранить результат партии"}` |

### Примеры запросов в терминале

```bash
# Получить историю
curl http://localhost:3000/api/games

# Сохранить результат (формат ТЗ — партия против компьютера)
curl -X POST http://localhost:3000/api/games \
  -H 'Content-Type: application/json' \
  -d '{"player_name":"Алиса","result":"win"}'

# Сохранить результат режима «2 игрока»
curl -X POST http://localhost:3000/api/games \
  -H 'Content-Type: application/json' \
  -d '{"x_name":"Алиса","o_name":"Борис","mode":"duo","result":"win"}'

# Очистить историю
curl -X DELETE http://localhost:3000/api/games
```

## 🗄 Схема базы данных

Используется **SQLite** через `better-sqlite3`. База хранится в файле
`database.sqlite`, который создаётся автоматически при первом запуске.

### Таблица `games`

| Поле | Тип | Ограничения | Назначение |
|---|---|---|---|
| `id` | INTEGER | `PRIMARY KEY AUTOINCREMENT` | Уникальный идентификатор записи |
| `x_name` | TEXT | `NOT NULL`, длина 1–30 | Имя игрока X (человек в режиме с ИИ, Игрок 1 в «2 игрока») |
| `o_name` | TEXT | `NOT NULL`, длина 1–30 | Имя игрока O («Компьютер» или Игрок 2) |
| `mode` | TEXT | `NOT NULL`, `ai` \| `duo` | Режим, в котором сыграна партия |
| `result` | TEXT | `NOT NULL`, `win` \| `lose` \| `draw` | Итог партии с точки зрения X |
| `played_at` | DATETIME | `DEFAULT CURRENT_TIMESTAMP` | Время окончания партии (UTC) |

Старые базы (схема с `player_name`) автоматически мигрируют при запуске:
данные сохраняются, ИИ-партии получают `o_name = 'Компьютер'` и `mode = 'ai'`.

### SQL-схема

```sql
CREATE TABLE IF NOT EXISTS games (
  id        INTEGER PRIMARY KEY AUTOINCREMENT,
  x_name    TEXT    NOT NULL
                    CHECK(length(trim(x_name)) BETWEEN 1 AND 30),
  o_name    TEXT    NOT NULL
                    CHECK(length(trim(o_name)) BETWEEN 1 AND 30),
  mode      TEXT    NOT NULL DEFAULT 'ai'
                    CHECK(mode IN ('ai', 'duo')),
  result    TEXT    NOT NULL
                    CHECK(result IN ('win', 'lose', 'draw')),
  played_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX IF NOT EXISTS idx_played_at ON games(played_at DESC);
```

### Заметки

- `CHECK`-ограничения — **второй рубеж** валидации после серверной проверки:
  даже если в обход сервера попытаться записать недопустимые данные, база их
  отклонит.
- Индекс `idx_played_at` ускоряет запрос истории — он выполняется при каждом
  открытии меню.
- `played_at` хранится в **UTC** в формате `YYYY-MM-DD HH:MM:SS`. Клиент
  переводит дату в локальный формат `ДД.ММ.ГГГГ ЧЧ:ММ`.
- Сортировка истории выполняется по `played_at DESC, id DESC` — так порядок
  остаётся стабильным, даже если у нескольких партий совпадает время.

### Посмотреть данные напрямую

```bash
# Через sqlite3 (если установлен)
sqlite3 database.sqlite "SELECT * FROM games ORDER BY played_at DESC LIMIT 10;"

# Или через Node
node -e "const db=require('better-sqlite3')('database.sqlite');console.table(db.prepare('SELECT * FROM games').all());"
```
`Ctrl + C` в терминале. База данных закроется корректно.

## ❓ Возможные проблемы и решения

### Порт 3000 уже занят

**Сообщение:** `Error: listen EADDRINUSE: address already in use :::3000`

**Причина:** порт уже используется другим процессом. Чаще всего это **старый
незакрытый сервер** — например, если предыдущий `npm start` не остановили через
`Ctrl+C`.

**Шаг 1 — проверьте, не запущен ли сервер уже.** Если в другом окне терминала
уже работает `npm start`, просто откройте http://localhost:3000 — всё в порядке.

**Шаг 2 — если нужно запустить заново, освободите порт:**

```bash
# macOS / Linux — остановить старый сервер
pkill -f "node server.js"

# Узнать, кто занимает порт
lsof -nP -iTCP:3000 -sTCP:LISTEN

# Точечно завершить конкретный процесс
kill <PID>
```

**Шаг 3 — или запустите на другом порту:**

```bash
PORT=5000 npm start
# затем откройте http://localhost:5000
```

---

### `Cannot find module 'better-sqlite3'`

**Причина:** зависимости не установлены.

```bash
rm -rf node_modules package-lock.json
npm install
```

---

### `file is not a database` при запуске

**Причина:** файл `database.sqlite` повреждён (например, прервана запись или
файл изменён вручную).

Приложение **намеренно** отказывается работать с повреждённой базой, чтобы не
терять данные молча. Решение — удалить файл, бада пересоздастся:

```bash
rm -f database.sqlite database.sqlite-shm database.sqlite-wal
npm start
```

---

### `SQLITE_CANTOPEN: unable to open database file`

**Причина:** нет прав на файл или каталог проекта.

```bash
chmod u+rw database.sqlite
```

Если файл создан другим пользователем — удалите его (см. выше) и перезапустите.

---

### Установился, но `npm start` не открывает страницу

`npm start` только запускает сервер — браузер открывать нужно вручную:
**<http://localhost:3000>**

### Игра не реагирует на клики

- Убедитесь, что поле не заблокировано: во время хода компьютера (≈0,4 с) поле
  временно неактивно — это защита от быстрых повторных кликов.
- Если партия завершена, нажмите **«Сыграть ещё»**, чтобы вернуться в меню.

### Не сохраняется результат партии

Посмотрите консоль браузера (F12) и вывод сервера в терминале. Если появилось
уведомление «Нет связи с сервером» — сервер не запущен. Сообщение с деталями
причины всегда выводится в stderr терминала, где запущен сервер.

---

### Имя не вводится полностью

Поле ограничено 30 символами: это требование задания, сервер тоже отклоняет
более длинные имена кодом `400`.

---

### Порт занят при повторном запуске, хочу начать с чистой базы

```bash
pkill -f 'node server.js'   # macOS / Linux
rm -f database.sqlite*
npm start
```

## 🏗 Архитектура

Приложение разделено на три слоя:

```
┌──────────────────────────────────────────────────────┐
│  PRESENTATION — public/                              │
│  index.html · style.css · script.js                  │
│  Правила игры, ИИ, запросы к API                     │
└───────────────────────┬──────────────────────────────┘
                        │ HTTP / JSON
┌───────────────────────▼──────────────────────────────┐
│  API — server.js                                     │
│  Маршруты, валидация, коды ответов, ошибки            │
│  (SQL здесь отсутствует)                             │
└───────────────────────┬──────────────────────────────┘
                        │ вызовы функций
┌───────────────────────▼──────────────────────────────┐
│  DATA — db.js                                        │
│  Схема БД, индексы, prepared statements              │
│  (здесь живёт весь SQL)                              │
└───────────────────────┬──────────────────────────────┘
                        │
┌───────────────────────▼──────────────────────────────┐
│  STORAGE — database.sqlite                           │
└──────────────────────────────────────────────────────┘
```

### Принятые решения

| Решение | Почему |
|---|---|
| `better-sqlite3` (синхронный) | Без внешних сервисов, без гонок, простой запуск |
| Валидация на сервере + `CHECK` в БД | Клиент недоверенный; сервер — источник истины |
| SQL только в `db.js` | Разделение слоёв, тестируемость, безопасность |
| Один `index.html` с двумя состояниями | Нет зависимостей и роутера |
| `textContent` для вывода | Защита от XSS по умолчанию |
| Синхронный доступ к БД | Простота: нет `async`/`await` в слое данных |

Подробное обоснование — в [`ARCHITECTURE.md`](ARCHITECTURE.md),
результаты проверок — в [`TEST_REPORT.md`](TEST_REPORT.md),
замечания по качеству кода — в [`REVIEW.md`](REVIEW.md).

## 🛠 Безопасность

| Угроза | Защита |
|---|---|
| SQL-инъекция | Prepared statements (`db.prepare(...).run/get/all`) — параметры не склеиваются со строкой запроса |
| XSS | Только `textContent` / `createElement`, `innerHTML` не используется |
| Невалидные данные | Валидация на сервере + `CHECK`-ограничения в БД |
| Переполнение запроса | Ограничение тела `16kb` |
| Утечка внутренних ошибок | Клиенту отдаётся нейтральное сообщение, причина — только в лог сервера |
| Повреждение БД | Приложение не стартует с битым файлом, вместо этого сообщает об ошибке |

Проверено фактически: попытки `x'; DROP TABLE games;--` и
`<script>alert(1)</script>` сохраняются как обычный текст и не влияют ни на
структуру базы, ни на безопасность страницы.

## 💡 Идеи для развития

### Ближайшие шаги

| Идея | Сложность | Описание |
|---|---|---|
| Кнопка «Повторить сохранение» | Низкая | Если сервер был недоступен в момент окончания партии, дать возможность досохранить результат |
| Умный ИИ (минимакс) | Низкая | Сделать компьютера действительно сложным: искать лучший ход, а не первый попавшийся |
| Счётчик побед | Средняя | Показывать статистику: сыграно партий, побед, ничьих, поражений |

### Среднесрочные

| Идея | Сложность | Описание |
|---|---|---|
| Рейтинг игроков | Средняя | Таблица со статистикой по именам, процент побед, сортировка истории по рейтингу |
| Выбор сложности | Средняя | Лёгкий / обычный / сложный — разные стратегии ИИ |
| Звук и анимации | Низкая | Звук при ходе и победе, плавная подсветка выигрышной линии |

### Долгосрочные

| Идея | Сложность | Описание |
|---|---|---|
| Онлайн-мультиплеер | Высокая | WebSocket-сервер, комнаты, синхронная партия между устройствами |
| Выбор размера поля | Средняя | Поле 4×4 и 5×5 (текущая логика завязана на `WINNING_LINES` для 3×3) |
| Игра с компьютером через API | Высокая | Перенести игровую логику на сервер — избавит от подмены результатов клиентом |
