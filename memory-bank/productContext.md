# Product Context

## Проблема, которую решает

Классическая «Крестики-нолики» в браузере обычно теряет результат партии, как
только закрыли вкладку. Здесь результат каждой партии автоматически уходит в
базу данных и остаётся видимым в истории — на том же устройстве, при следующем
запуске сервера.

Вторая задача — учебная: показать полный цикл разработки от проектирования
архитектуры до ревью и документации (методология Harness с 5 ролями).

## Целевая аудитория

| Аудитория | Что им нужно |
|---|---|
| Игрок | Быстро начать партию, не вводя ничего лишнего |
| Новичок-разработчик | Понять, как устроены слои и почему так, а не иначе |
| Проверяющий | Быстро запустить и увидеть рабочий результат |

## Пользовательские сценарии

1. **Начало игры.** Игрок вводит имя → нажимает «Начать игру» → попадает на
   поле 3×3. Пустое имя → понятная ошибка, игра не начинается.
2. **Партия.** Игрок кликает клетку → ставится X → через ~0,4 с компьютер
   отвечает O. Победа или ничья определяются и объявляются.
3. **Автосохранение.** После окончания партии результат сам уходит на сервер.
   При ошибке сети — уведомление (но повторить сохранение нельзя, см. NTH-3).
4. **История.** При возврате в меню подгружаются последние 10 игр: имя,
   результат, дата.
5. **Очистка.** Кнопка «Очистить историю» с подтверждением удаляет все записи.
6. **Ещё раз.** Кнопка «Сыграть ещё» возвращает в меню, имя остаётся в поле.

## UX-решения

| Решение | Почему |
|---|---|
| Один `index.html` с двумя экранами | Без роутера и зависимостей; состояние переключается флагом `hidden` |
| Только `textContent`, никогда `innerHTML` | XSS невозможен по умолчанию |
| Подпись «Вы играете за X, компьютер — за O» | Новичок сразу понимает правила без чтения |
| Имя остаётся в поле после партии | Удобно начать вторую партию |
| `confirm()` перед очисткой истории | Защита от случайной потери данных |
| Тосты для ошибок сети | Обратная связь без модальных окон |
| `maxlength="30"` на поле ввода | Проблема: сообщение об ошибке становится недостижимым (MINOR-3) |

## Известный компромисс

Игровая логика целиком на клиенте. Это упрощает разработку и позволяет делать
ходы мгновенно, но означает, что результат формируется браузером, а сервер
ему доверяет. Для учебного проекта приемлемо; в продакшене логику нужно
переносить на сервер (отмечено в roadmap `README.md`).
