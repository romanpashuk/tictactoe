## Ключевые технические решения

| Решение | Почему так |
|---|---|
| `better-sqlite3` (синхронный) | Нет внешних сервисов, нет гонок, простой запуск |
| Валидация в 3 слоя | Клиент недоверенный; сервер — истина; БД — страховка |
| SQL только в `db.js` | Разделение слоёв, тестируемость, безопасность |
| Один `index.html`, 2 состояния | Без зависимостей и роутера |
| `textContent` для вывода | XSS невозможен по умолчанию |
| Лимит 10 задаётся в SQL (`LIMIT`) | Меньше трафика, работает с индексом |
| Синхронный доступ к БД | Нет `async`/`await` в слое данных |
| `DB_PATH` через `process.env` | Тестируемость: проверка битой БД без вреда рабочей |

## Паттерны кода

**Роуты** — три функции в `server.js`, каждая оборачивает вызов `db.*` в
`try/catch`. Валидация вынесена в отдельную чистую функцию
`validateGameBody(body)`, возвращающую `{ok, data}` или `{ok, error}` — без
знания об HTTP.

**Доступ к БД** — `db.js` экспортирует 4 функции (`listGames`, `createGame`,
`clearGames`, `getDb`) и константы (`ALLOWED_RESULTS`, `ALLOWED_MODES` и др.).
Везде `db.prepare(...).run/get/all`. `getDb()` лениво инициализирует БД, если
`initDb()` не вызывался — страховка от неправильного порядка инициализации.
`initDb()` содержит миграцию схемы v1→v2 (пересборка таблицы).

**Фронтенд** — `script.js` разбит на секции с рамками `── Название ──`.
Состояние в модульных переменных: `board`, `gameMode` (`ai`|`duo`),
`xPlayerName`, `oPlayerName`, `currentTurn`, `isGameActive`, `isThinking`.
В duo-режиме `isThinking` не выставляется и задержки ИИ нет. Таймеры
`aiTimer` и `toastTimer` отменяются явно.

**Ошибки** — на клиенте центральная функция `apiRequest()`: ловит и сетевые
сбои, и не-JSON ответы, и коды `!response.ok`, отдавая текст на русском.
На сервере — middleware с 4 аргументами перехватывает ошибки парсера JSON.

## Поток данных

**Запись результата (основной сценарий):**

```
клик по клетке → handleCellClick() → makeMove() → evaluateGameState()
  → finishGame() → saveGameResult() → apiRequest() → fetch POST /api/games
  → server.js: validateGameBody() → db.createGame() → prepared INSERT
  → 201 {id, x_name, o_name, mode, result, played_at, player_name}
  → showToast('Результат сохранён')
```

В режиме `duo` после хода компьютера нет: `handleCellClick()` просто
переключает `currentTurn` на второго человека.

**Чтение истории:**

```
открытие меню / возврат «Сыграть ещё» → showMenuScreen() → loadHistory()
  → apiRequest('/api/games') → GET → db.listGames(10)
  → SELECT ... ORDER BY played_at DESC, id DESC LIMIT 10
  → массив → цикл создаёт <tr> через createElement + textContent → tbody
```

## Проверка целостности файлов

У проекта нет автоматической проверки HTML/CSS на синтаксис. Добавлен
`css-check.js`, потому что два бага со скобками прошли 85 других проверок:

| Что проверяет | Зачем |
|---|---|
| Баланс фигурных скобок | Незакрытая скобка превращает последующие правила во вложенные |
| Ключевые селекторы на верхнем уровне | Вложенный `.board` = `.table-wrap .board` не применится |
| Тёмная тема, `@media <480px` | Фичи из ТЗ, которые иначе не отследить |
| Связь `index.html` ↔ `style.css` | У каждого `#id` должны быть стили |

**Перед правкой HTML/CSS всегда проверяй баланс скобок:**
```bash
node css-check.js
```

## Секреты и подводные камни

- `board[winningLine[0]]` определяет, чья победа — X игрока, O компьютера.
- Проверка победы обязана идти **до** проверки ничьей, иначе последний ход
  в ничью будет засчитан как победа.
- `textContent` вместо `innerHTML` — не украшение, а требование безопасности;
  в коде есть комментарий об этом на 5-й строке.
