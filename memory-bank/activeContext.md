## Режим «2 игрока» — ключевые решения

| Решение | Зачем |
|---|---|
| Схема v2: `x_name`, `o_name`, `mode` вместо `player_name` | Два игрока + отметка режима партии |
| Миграция v1→v2 в `initDb()` (пересборка таблицы) | SQLite не меняет CHECK через ALTER; данные сохраняются (id, дата, имена) |
| `result` остался `win/lose/draw` от лица X | В режиме с ИИ человек всегда X — смысл старых записей не меняется |
| Legacy-совместимость API | ТЗ (`promt.md`) требует `{player_name, result}` и `player_name` в ответах — принято и то, и другое (`player_name ≡ x_name`) |
| В `duo` нет `isThinking` и задержки ИИ | Ходы людей идут подряд, поле всё время активно |
| История: duo-строка = «Алиса vs Борис», победитель по имени | В «2 игрока» «поражения» для кого-то из двоих нет — обе победы зелёные |

## Важные заметки для следующей сессии

1. 🔴 **Не рассчитывай на автозагрузку правил.** Проверено фактически:
   `.clinerules/memory-bank.md` в контекст сессии **не попадает**.
   **Действие:** первым делом читай `memory-bank/activeContext.md`, затем
   остальные 5 файлов. Инструкция есть в начале `README.md`.
2. **Memory Bank может отставать от кода** — если видишь расхождение, верь коду
   и обнови нужный файл.
3. **После любых правок запускай `npm run test:all`** — сейчас 5 наборов,
   **146 проверок**. Требуется запущенный сервер (e2e).
4. **Не оставляй фоновые процессы `node server.js`** — держат порт 3000.
   Проверка: `lsof -nP -iTCP:3000 -sTCP:LISTEN`. После проверок — `kill`.
5. **`database.sqlite` в `.gitignore`** — БД создаётся автоматически; старые БД
   мигрируют на схему v2 при первом запуске.
6. **`database.sqlite` содержит локальную историю в схеме v2** — миграция уже
   выполнена (05.10.2026).
7. **Файл `memory-bank-init.md`** — ТЗ на создание Memory Bank; `promt.md` —
   ТЗ на саму игру. Не путать.
8. **Не переписывать код целиком** при мелких правках — это уже привело
   к двум багам с потерей скобок (в `script.js` и в `style.css`).
9. **Перед правкой HTML/CSS проверяй баланс скобок:** `node css-check.js`.
